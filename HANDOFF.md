# bAIble v2 — Handoff

A handoff is a durable transfer contract between humans, agents, tools or sessions.

## Role and authority

- From role
- To role
- Authority boundary
- Approval still required

## Minimal contract

- Task ID
- Intent
- Current state
- Scope / out of scope
- Dependencies
- Authorized sources
- Verified sources
- Applicable rules
- Known facts / observations
- Interpretations / assumptions
- Unknowns / missing context
- Conflicts
- Work completed
- Actual evidence
- Verification result
- Expected output
- Expected evidence
- Open questions
- Risks / limitations
- Next authorized transition
- Recovery / rollback notes where relevant

## Rules

1. Preserve scope and authority.
2. Preserve uncertainty, missing context and contradictions.
3. Distinguish completed work from proposed next work.
4. Link claims to evidence where practical.
5. Never imply access, action, test, verification or certainty that did not occur.
6. Do not convert a lifecycle state into an epistemic claim.
7. Receiving workers should not need hidden conversational context to continue a bounded task.

A handoff is not a conversational “good luck”.
