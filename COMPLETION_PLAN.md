# bAIble v2 — Completion Plan

Status: ACTIVE CONSOLIDATION PLAN

Goal: produce the strongest living bAIble v2 we can currently justify from public bAIble history, FederAItion implementation/evidence and UnAiversed context relationships, without pretending that unverified ideas are canonical truth.

## Stage 1 — Inventory
Source families:
- original public bAIble,
- bAIble pre-v2 laboratory,
- current bAIble-v2,
- FederAItion runtime / decisions / evidence / research,
- UnAiversed maps and context records,
- current human-approved design decisions from active collaboration.

Output: coverage matrix with KEEP / MERGE / REWRITE / HISTORY / ARCHIVE / DROP candidates.

## Stage 2 — Meaning recovery
For each major concept, recover:
- original purpose,
- current purpose,
- provenance,
- implementation status,
- evidence,
- known drift,
- public/private boundary.

Special attention: Reality Check, Fact Check, rAIda, Watchdog, WheeAIls, Wolf, Context Item, UnAiversed, handoff, evidence, verification, lessons.

## Stage 3 — Contradiction scan
Do not return generic yellow.

For each contradiction record:
ID, claim A/source A, claim B/source B, type, scope, unresolved point, evidence, resolution check, blocked/not blocked.

## Stage 4 — Redundancy map
Collapse duplicate onboarding/bootstrap routes into canonical documents while preserving unique material.

## Stage 5 — Ecosystem integration
Build one canonical graph:
HI + AI ↔ bAIble + FederAItion + UnAiversed,
with typed systems, mechanisms, roles, relations, failure modes and major milestones.

## Stage 6 — Two primary navigation views
Maintain:
- Human View,
- AI / Agent View.

They share one graph but optimize for different questions.

## Stage 7 — Operational contracts
Make explicit:
- coordination protocol,
- handoffs,
- authority boundaries,
- public/private rules,
- evidence requirements,
- verification,
- continuation,
- stop conditions.

## Stage 8 — Learning system
Preserve:
`EXPERIENCE → CANDIDATE → GENERALIZE → VALIDATE → INTEGRATE → REVIEW AGAIN`

Frequency is a signal for investigation, not automatic canonization.

## Stage 9 — Failure-mode integration
Attach failure modes to affected mechanisms. Include Context Drift, Meaning Drift, Scope Drift, False Done, Record ≠ Truth, Decision ≠ Truth, Agent Echo Chamber, White-Couch Failure, Automation Without Authority, User Adaptation Hides Failure, Memory Inflation and Yellow Without Explanation.

## Stage 10 — Navigation cleanup
README and START_HERE should link to the canonical path rather than duplicate whole documents.

## Stage 11 — Self-audit
Check:
- references exist,
- roles and authority are explicit,
- public/private boundary is intact,
- claims are correctly classified,
- implementation claims have evidence,
- RC and FC remain distinct,
- no private implementation detail leaked into public governance,
- no important legacy concept disappeared merely because its file was merged.

## Stage 12 — Verification
Use repository inspection and appropriate runtime/tests. A runtime pass verifies only the exercised runtime behavior; it does not verify editorial completeness.

## Stage 13 — Living release
Mark current v2 as a living baseline, not a final immutable doctrine.

Each future material change should preserve:
origin → reason → evidence → scope → verification → next review.
