# bAIble v2 — Roles

## Original foundation roles

These roles were explicit in bAIble v0.1 and remain useful as execution responsibilities:

- **Human / Product Owner** — owns intent, product decisions, acceptance and material authority.
- **Architect** — reasons about system structure, boundaries and architectural consequences.
- **Developer** — implements bounded technical changes.
- **QA** — tests the required behavior and reports actual results.
- **Reviewer** — looks for defects, regressions, security/scope problems and inconsistencies.
- **Documentation Agent** — records durable knowledge, provenance, decisions and lessons.

These are responsibilities, not necessarily separate AI instances.

## Coordination roles

- **bAIble** — governance and language.
- **rAIda** — THINK / COORDINATE / REMEMBER-TO-CHECK.
- **Reality Check** — VERIFY alignment and evidence boundary.
- **Watchdog** — CONTINUE / MONITOR / ESCALATE.
- **UnAiversed** — relationships and context maps.
- **WheeAIls** — relevant reminders.
- **Wolf** — ORIENT / TEACH / ONBOARD.

## Agent boundary

“Agent” is a generic execution category, not a replacement for the responsibilities above. A concrete agent may perform one or several roles only when its authority and scope are explicit.

No role silently acquires another role's authority.
