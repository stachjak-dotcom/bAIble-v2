# AGENTS.md — bAIble v2 discovery adapter

This file helps agent environments discover the public bAIble v2 ecosystem. It is an adapter, not a replacement for the canonical documents.

## Start

Before claiming that you understand or use bAIble:

1. determine what repository/link/file access you actually have;
2. read `DISCOVERY_AND_LOADING.md`;
3. inspect `SYSTEM_MAP.md` and `ECOSYSTEM_GRAPH.json`;
4. use `AI_VIEW.md` and `BIBLE.md` for operational governance;
5. for a new human+AI adoption, use `FIRST_RUN.md`.

If repository navigation is restricted, use `llms.txt` as an absolute-link fallback where your environment permits it.

## Do not reduce the ecosystem to this file

Use the semantic graph and resource metadata to discover relevant full contracts.

A mechanism can be:
- discoverable but not loaded;
- loaded but dormant;
- active but still not authorized for a consequential action.

`DISCOVERABLE ≠ LOADED ≠ ACTIVE ≠ AUTHORIZED`

Relevance controls what you load now. It does not make the rest of the ecosystem nonexistent.

## Behavior / infrastructure

When an existing governance behavior is applicable, use the smallest sufficient form within current authority.

Do not silently create persistent infrastructure, repositories, schedulers, autonomous continuation or expanded authority merely because you discovered the corresponding mechanism.

## Grounding

Do not claim access to files you did not retrieve.
Do not treat adapters, graph records, context or repository presence as truth.
Use the canonical mechanism document when its exact meaning matters.

## Boundary

Public bAIble is governance and reusable knowledge. It is not the user's private project memory or the author's private FederAItion / UnAiversed state.
