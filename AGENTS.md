# AGENTS.md — bAIble v2 discovery adapter

This file helps agent environments find bAIble v2. It points to the canonical documents and redefines nothing.

## Start

Before claiming that you understand or use bAIble:

1. determine what repository, link or file access you actually have;
2. read `OPERATING.md` (discovery, preflight, routing, blocking states);
3. read `ECOSYSTEM.md`, `ECOSYSTEM_GRAPH.json` and `vocabulary.json`;
4. use `BIBLE.md` for the rules and the work loop;
5. for a new human + AI adoption, continue with `ONBOARDING.md`.

If repository navigation is restricted, use `llms.txt` as an absolute-link fallback where your environment permits it.

## Reminders

- `DISCOVERABLE ≠ LOADED ≠ ACTIVE ≠ AUTHORIZED`. Relevance controls what you load now; it does not make the rest of the ecosystem nonexistent.
- Use the smallest sufficient existing behaviour; do not create infrastructure, repositories, schedulers or expanded authority because you discovered a mechanism.
- Do not claim access to files you did not retrieve. Adapters, graph records, context and repository presence are not truth.
- Public bAIble is not anyone's private project memory or private FederAItion / UnAiversed state.
- `history/` explains how bAIble was built; it is not active guidance.
