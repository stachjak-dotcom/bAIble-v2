# bAIble v2 — Ecosystem Map

bAIble v2 is best understood as one living human–AI ecosystem with three tightly coupled systems:

- **bAIble** — governance, language, rules, lessons, verification discipline and reusable working patterns.
- **FederAItion** — runtime, orchestration, evidence, durable decisions, implementation state and private operational memory.
- **UnAiversed** — contextual and relational mapping space: what relates to what, under which scope, meaning, provenance and time.

Human Intelligence (HI) and Artificial Intelligence (AI) are participating entities that create, use, inspect and evolve this ecosystem. Neither is represented as an infallible authority.

## Canonical division of responsibility

- Human — intent, material decisions, acceptance and intervention gates.
- AI / Agent — PREPARE / REASON / EXECUTE / RECORD within explicit scope.
- bAIble — governance and generalized learning.
- rAIda — THINK / COORDINATE / REMEMBER-TO-CHECK.
- UnAiversed — map relationships and context; never silently promote them to truth.
- WheeAIls — surface relevant reminders and support; never become authority.
- Wolf — ORIENT / TEACH / ONBOARD.
- Reality Check — ALIGN human and AI working maps.
- Fact Check — VERIFY claims, facts, assumptions and evidence.
- Verification — test whether the required result actually holds.
- Watchdog — CONTINUE / MONITOR / ESCALATE only through authorized transitions.
- Repository / durable artifacts — preserve inspectable history and evidence.

## Core working flow

`INTENT → CONTEXT → GROUNDING → RULES → PLAN → APPROVAL → ACTION → EVIDENCE → VERIFICATION → ACCEPTANCE → LEARN → PERSIST`

Parallel alignment loop:

`HUMAN MAP ↔ AI WORKING MAP → AGREEMENT / DIVERGENCE / MISSING CONTEXT → NEXT CHECK`

Parallel factual loop:

`CLAIM → SOURCE / EVIDENCE → CHECK → SUPPORTED / CONTRADICTED / UNCERTAIN / MISSING_EVIDENCE → NEXT CHECK`

## Level-4 map model

The ecosystem can be rendered at four simultaneous levels:

1. **Constellations** — bAIble, FederAItion, UnAiversed, HI, AI.
2. **Systems** — rAIda, Watchdog, Reality Check, Fact Check, verification, onboarding, context, learning.
3. **Mechanisms** — preflight, scope checks, handoffs, approvals, evidence, Context Items, task state, public/private boundaries.
4. **Atomic relations** — origin, claim, observation, interpretation, authority, dependency, test, contradiction, refinement, supersession, timing, visibility and next check.

## Typed relationships

Relationships are first-class and should be explicit when material:

`contains`, `belongsTo`, `coordinates`, `invokes`, `observes`, `verifies`, `producesEvidenceFor`, `dependsOn`, `protects`, `constrains`, `teaches`, `remembersToCheck`, `contradicts`, `refines`, `supersedes`, `derivedFrom`, `originatedFrom`, `appliesTo`, `handsOffTo`, `monitors`, `escalatesTo`, `authorizes`, `blocks`, `exposesRiskTo`, `learnsFrom`, `represents`, `linksContextTo`, `requiresHumanDecision`.

A relationship is not proof merely because it exists.

## Design rule

The map must not merely show what exists. It should show why it exists, what it relates to, what can trust it, who may act on it, what evidence supports it and what happens when it fails.
