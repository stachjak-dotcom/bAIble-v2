# bAIble v2 — Experiments

Experiments are bounded investigations, not hidden production changes and not a mandatory step for every lesson.

Record: ID, question, hypothesis, setup, input, expected, actual, evidence, failure/surprise, interpretation, alternative explanation, lesson, candidate change and verification.

A useful experiment loop is:

`QUESTION → HYPOTHESIS → SETUP → ATTEMPT → RESULT → INTERPRETATION → WHAT IT SUPPORTS → WHAT IT DOES NOT SUPPORT → NEXT CHECK`

A successful experiment must not confirm a broader claim than the conditions actually tested.

Experiments feed the broader learning lifecycle:

`OBSERVATION / EXPERIENCE / FAILURE / EXPERIMENT → LESSON CANDIDATE → GENERALIZATION CHECK → VALIDATION → PERMANENT LESSON / RULE CANDIDATE`

One observation, one experiment or repeated occurrence does not automatically become a permanent rule. Frequency can trigger investigation without proving the cause.

## Closing an experiment

An experiment should not remain in normal active context merely because it once produced useful work.

`EXPERIMENT → RESULT → CLASSIFY OUTPUT → EXTRACT ACTIVE VALUE → VERIFY DESTINATIONS → ARCHIVE / RETAIN REMAINDER`

Classify material separately when applicable:
- reusable or accepted value;
- lesson/rule candidate;
- unresolved question or next check;
- rejected or superseded mechanism/interpretation;
- evidence/provenance;
- historical remainder.

Do not archive a mixed experiment before useful active value and unresolved obligations have an explicit destination.

Archiving is not an epistemic verdict.

`ARCHIVED ≠ FALSE`

`EXPERIMENT RESULT ≠ ACTIVE MECHANISM ≠ CANON`

Archive location and physical layout are implementation choices. Preserve enough provenance to reconstruct what was extracted, where it went, and what remained historical.
