# Start Here

bAIble is a living public guide for humans and AI working together deliberately.

The shortest route:

`UNDERSTAND → CLASSIFY → PLAN → ACT → VERIFY → ALIGN → LEARN → PERSIST`

Start with BIBLE, LANGUAGE, ARCHITECTURE, ONBOARDING, VERIFICATION, FACT_CHECK, REALITY_CHECK, CONTEXT_AND_MEMORY, HANDOFF and PUBLIC_PRIVATE_BOUNDARY.

The public bAIble is not project memory. Project context, evidence, implementation and secrets belong in appropriate private systems.

rAIda coordinates. UnAiversed maps context and relationships. Watchdog monitors observable workflows. Reality Check compares human and AI working maps. Fact Check verifies claims and evidence. Wolf teaches orientation.

Use Reality Check when the problem may be misunderstanding, meaning drift or context drift.
Use Fact Check when the problem is whether a claim is actually supported.

## Living-document rule

bAIble grows from observed work, not from plausible-sounding rules.

`EXPERIENCE → CANDIDATE → GENERALIZE → VALIDATE → INTEGRATE → REVIEW AGAIN`

Repeated failure is a signal to inspect the surrounding way of working. It is not by itself proof of the cause or permission to create another permanent rule.

Preserve provenance and old meaning when concepts evolve. A surviving name does not guarantee semantic continuity.

Start small. Learn as you go. Build only what solves a real problem.
