# bAIble v2 — Origin and Purpose

bAIble exists to make human–AI collaboration repeatable, inspectable, verifiable and able to improve through use without turning collaboration into rigid ceremony.

Fluent output is not evidence that a request was understood, an action was authorized, work actually happened, or the result can be reproduced.

The living process is:

`UNDERSTAND → CLASSIFY → PLAN → ACT → VERIFY → ALIGN → LEARN → PERSIST`

## What bAIble is

A public governance and learning layer for:
- reusable rules and guardrails,
- collaboration language,
- roles and authority,
- verification and evidence discipline,
- context and handoff contracts,
- lessons, evaluations and onboarding.

## What bAIble is not

It is not:
- the user's private memory,
- a private-project source of truth,
- proof of execution,
- a required software package,
- a replacement for human decisions,
- a place for credentials or confidential implementation data.

## Relationship to the wider ecosystem

bAIble, FederAItion and UnAiversed form one ecosystem with different responsibilities:

- bAIble generalizes governance and lessons,
- FederAItion holds operational runtime, evidence and durable implementation context,
- UnAiversed maps relationships and perspectives.

Human and AI participate in and evolve the ecosystem.

The public layer teaches the method. Private operational layers hold project-specific evidence and implementation.

Reality outranks documentation. If the real world contradicts the map, update the map.
