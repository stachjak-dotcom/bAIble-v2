# bAIble v2 — Context & Memory

## Core rule
REMEMBER-TO-CHECK, NOT REMEMBER-EVERYTHING.

A durable Context Item should preserve, where relevant: stable id, type, provenance, scope, status, visibility, observation, claim, interpretation, sources, evidence, relations, time/version, limitations and next check.

Lifecycle: OBSERVED → CANDIDATE → TESTED → CONFIRMED / REJECTED / UNCERTAIN.

Useful relations: supports, contradicts, refines, supersedes, derivedFrom, dependsOn, testedBy, verifiedBy, originatedFrom, appliesTo.

Old context may be correct but irrelevant, stale, incomplete, superseded, contradictory, private or out of scope.

Forbidden for material decisions: OLD MEMORY → NEW ASSUMPTION → ACTION.
Prefer: CONTEXT → CHECK RELEVANCE → GROUND → DECIDE → ACT.

UnAiversed is a relationship map, not a truth store.
