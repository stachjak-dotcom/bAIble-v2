# bAIble v2 — Meaningful Milestones

History is included only where it explains current structure or protects meaning.

## Foundation — bAIble v0.1
Established the core discipline: understand before implementing, make completion testable, preserve memory, respect scope, separate implementation from verification, and use explicit roles.

## Durable context / FederAItion
The project moved from conversation-only continuity toward durable evidence, decisions, lessons, task state and recoverable context.

## UnAiversed
Context was reframed from a flat memory store into a relationship space from which different maps can be assembled for different purposes.

## Reality Check restoration
Reality Check was restored to its original role: comparing human and AI working maps.

## Fact Check split
Factual/evidential verification behavior that had accumulated under Reality Check became a separate mechanism.

## rAIda
The orchestrator became a concrete runtime direction: THINK / COORDINATE / REMEMBER-TO-CHECK rather than “remember everything”.

## Watchdog separation
Continuity monitoring was separated from orchestration and verification so that monitoring could not silently acquire authority.

## Context Item contract
Context became addressable with origin, scope, status, visibility, evidence, relations, time, limitations and next check.

## Ecosystem synthesis
bAIble, FederAItion and UnAiversed are treated as one ecosystem with different responsibilities, with HI and AI as participating creators rather than subordinate components.

These milestones are explanatory anchors, not a full project chronology.
