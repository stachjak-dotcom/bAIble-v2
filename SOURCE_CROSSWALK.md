# bAIble v2 — Source Crosswalk

Status: CURRENT SYNTHESIS / PUBLIC-SAFE GENERALIZATION

This file records what the living v2 intentionally carries forward from the three source domains. It is a crosswalk, not proof that every source statement is canonical.

## 1. Original bAIble foundation

Carried forward:
- understand before implementing;
- observable expected result;
- completion must be testable;
- do not guess material requirements;
- respect scope;
- preserve durable memory;
- experiment ≠ production;
- implementation ≠ verification;
- human authority over material product/security/irreversible decisions;
- explicit roles: Human/Product Owner, Architect, Developer, QA, Reviewer, Documentation Agent;
- lAInguage: Explore / Propose / Prepare / Implement / Verify / Review;
- handoff discipline;
- agent eval scenarios;
- lessons should generalize from evidence rather than from one attractive story.

Current v2 locations:
BIBLE.md, AGENT_ROLES.md, HANDOFF.md, VERIFICATION.md, LANGUAGE.md, LESSONS_LEARNED.md.

## 2. bAIble pre-v2

- self-audit before publication;

## 3. FederAItion

Carried forward as generalized governance/architecture:
- rAIda = THINK / COORDINATE / REMEMBER-TO-CHECK;
- repository = durable memory;
- agent = bounded execution/reasoning;
- Watchdog = continuity, not intent;
- task state and authorized transitions;
- preflight orientation around role, scope, sources, rules, expected evidence and open questions;
- live-runtime evidence is distinct from simulation/unit tests;
- actual execution evidence matters more than agent narration;
- private runtime evidence must not be mirrored into public bAIble.

FederAItion remains the project/runtime implementation domain. Public bAIble describes reusable contracts, not private run details.

## 4. UnAiversed

Carried forward:
- explicit relationship map;
- human-map and AI-map as different views over shared context;
- context before conclusion;
- available context ≠ current intent;
- implemented ≠ verified;
- observations/hypotheses/patterns/decisions/lessons remain distinguishable;
- frequency is a signal, not proof;
- context map is not hidden model memory and not truth;
- provenance and relationships must remain inspectable;
- different purposes can generate different views from the same underlying graph.

Current v2 locations:
SYSTEM_MAP.md, HUMAN_VIEW.md, AI_VIEW.md, RELATIONSHIP_MODEL.md, CONTEXT_ITEM.md, CONTEXT_AND_MEMORY.md.

## 5. Foundational grounding

Carried forward:
USER_INPUT → RECORD → INTERPRETATION → CONFIRMATION/EVIDENCE → DECISION → LESSON/PATTERN.

Important consequences:
- user input must not be silently rewritten as AI interpretation;
- grammatical parsing does not prove intended meaning;
- high-impact interpretations require stronger confirmation;
- repeated failure can become a candidate pattern, but not automatically a permanent rule;
- origin, interpretation, confidence and decision should remain separable.

## 6. Current ecosystem synthesis

The present living model is:

HI + AI
↕
bAIble ↔ FederAItion ↔ UnAiversed

with:
- Reality Check = ALIGN human and AI working maps;
- Fact Check = VERIFY factual/evidential claims;
- Verification = does the required result actually hold?;
- rAIda = coordinate authorized work and remember what must be checked;
- Watchdog = maintain continuity through authorized transitions;
- Wolf = orient/teach/onboard;
- WheeAIls = relevant reminders;
- Repository = durable memory;
- Human = material decisions and intervention gates;
- Agent = prepare/reason/execute/record.

## 7. Explicit unresolved areas

- exact UI for Human View and AI View;

## 8. Current contradictions / tensions

### C-001 — Reality Check wording across older material
Older material sometimes used Reality Check as broad factual verification.
Current v2 splits:
- RC = map alignment,
- FC = factual/evidential checking.

Resolution:
older use is treated as historical semantic broadening; v2 preserves the split explicitly.

### C-002 — “memory” versus “context management”
Older language sometimes implies durable memory as a store.
Current model prefers:
REMEMBER-TO-CHECK, NOT REMEMBER-EVERYTHING.

Resolution:
memory remains a durable substrate; relevance/activation is a separate context-management problem.

### C-003 — UnAiversed as map versus source of truth
Some operational notes can look authoritative simply because they are stored in UnAiversed.
Current rule:
UnAiversed is a relationship/context space, not automatic truth.

Resolution:
truth/authority must come from appropriate evidence, decision authority and verification, not storage location.

## 9. Migration discipline

FOUND ≠ UNDERSTOOD ≠ VERIFIED ≠ CANONICAL.

A source item enters v2 only after its current meaning, scope and boundary are understood.
