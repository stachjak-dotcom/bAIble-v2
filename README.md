# bAIble v2

The shared bible of humans and AI working together: rules, principles, roles and the know-how of collaboration, public so that anyone can start and so that what we learn can be passed on.

Status: living baseline. It changes through evidence and experience ([STATUS.md](STATUS.md)).

## Why it exists

Human–AI collaboration should be repeatable, inspectable, verifiable and able to improve through use, without turning into rigid ceremony.

Fluent output is not evidence that a request was understood, an action was authorized, work actually happened, or the result can be reproduced.

**bAIble is** a public governance and learning layer: reusable rules and guardrails, collaboration language, roles and authority, verification and evidence discipline, context and handoff contracts, lessons, evaluations and onboarding.

**bAIble is not** your private memory, a private-project source of truth, proof of execution, a required software package, a replacement for human decisions, or a place for credentials or confidential data.

## The ecosystem in one breath

- **bAIble** — the shared rules and how to work together. Public.
- **FederAItion** — the working machinery: checks, sequences, continuation, evidence; and the reminder that human and AI understanding differ. Private.
- **UnAiversed** — the shared space of understanding where everyone can meet and recall only what is needed now. Not a truth store.

HI (human intelligence) and AI create, use and evolve all three. Details: [ECOSYSTEM.md](ECOSYSTEM.md).

## Where to start

**If you are an AI / agent:** first establish what you can actually access, then read [OPERATING.md](OPERATING.md). It is the operating contract: discovery and loading, preflight, when each mechanism applies, blocking states. Do not jump straight to setup advice because [ONBOARDING.md](ONBOARDING.md) is easy to find.

`DISCOVER ACCESS → DISCOVER ECOSYSTEM → CLASSIFY START STATE → RECOMMEND NEXT STEP`

**If you are new (human + AI):** read [ONBOARDING.md](ONBOARDING.md). It is the practical path through one real project. Do not copy somebody else's private ecosystem; build or reuse only what your own work needs.

**If you are human and want to steer:** keep reading this page, then [BIBLE.md](BIBLE.md) and [REALITY_CHECK.md](REALITY_CHECK.md).

## Four questions that must not collapse into one

- **Reality Check:** Do human and AI currently understand the same thing in the same way?
- **Fact Check:** Is this claim actually supported?
- **Verification:** Does the required result actually hold?
- **Acceptance:** Does the authorized human or system accept the verified result?

## For humans: what you should always be able to see

- Where are we, and what are we trying to achieve?
- What does the AI currently think the goal is?
- What is known, assumed, missing or disputed?
- What is happening now, and who or what may act?
- What needs my decision?
- What evidence exists, and what has actually been verified?
- What remains unresolved, and what happens next?

Your journey: `GOAL → SHARED MAP → SCOPE → PLAN → APPROVAL WHEN NEEDED → OBSERVABLE ACTION → EVIDENCE → CHECK → ACCEPT / CORRECT → LEARN`

**You keep authority over** product intent, material trade-offs, irreversible or high-impact decisions, the public/private destination of sensitive context, acceptance where it is required, and intervention at defined gates. Human authority is not factual infallibility: human claims may still need Fact Check, and human and AI maps may still need Reality Check.

**A good interface keeps apart** received information, AI interpretation, factual claim, evidence, decision, open question, contradiction, risk, proposed next action, action already performed and verified result. Never collapse these into one generic "done".

**Watch for** repeated manual correction that hides a systemic failure, approving without understanding scope, treating fluent explanation as evidence, using old context because it is convenient, assuming several agreeing agents are independent evidence, and turning every recurring failure into a permanent rule without diagnosis. The human view should reveal these patterns without taking human agency away.

## Living rule

Start small. Learn as you go. Build only what solves a real problem. Preserve provenance and old meaning when concepts evolve: a surviving name does not guarantee semantic continuity.

Reality outranks documentation. If the real world contradicts the map, update the map.
