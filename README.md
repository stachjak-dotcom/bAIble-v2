# bAIble v2

Status: **ECOSYSTEM BASELINE COMPLETE — living system**

The living public governance layer for disciplined human–AI work.

## Core loop

`INTENT → CONTEXT → GROUNDING → RULES → PLAN → ACTION → EVIDENCE → VERIFICATION → ACCEPTANCE → LEARN → PERSIST`

FOUND ≠ UNDERSTOOD ≠ VERIFIED ≠ CANONICAL

IMPLEMENTED ≠ VERIFIED ≠ ACCEPTED

CONTEXT CONTINUITY ≠ MEANING CONTINUITY

RECORD ≠ TRUTH

RELATION ≠ EVIDENCE

## Ecosystem

bAIble, FederAItion and UnAiversed are treated as one coordinated ecosystem with distinct responsibilities.

HI (Human Intelligence) and AI (Artificial Intelligence) are active participants that create, use and evolve the system.

- bAIble — governance, language, roles, lessons and reusable workflows.
- FederAItion — runtime/project coordination, state, execution and durable evidence.
- UnAiversed — contextual relationship space and multiple views; not truth.

## AI / agent entry

If you are an AI / agent, **do not begin from `FIRST_RUN.md` alone**.

First use [DISCOVERY_AND_LOADING.md](DISCOVERY_AND_LOADING.md) to establish what you can actually access and how to discover the public ecosystem. Then use [SYSTEM_MAP.md](SYSTEM_MAP.md) + [ECOSYSTEM_GRAPH.json](ECOSYSTEM_GRAPH.json) to understand what capabilities exist and where their canonical contracts live.

Only after that should a new-user adoption continue through [FIRST_RUN.md](FIRST_RUN.md).

bAIble exposes the complete public ecosystem without requiring every agent to preload every document.

For AI/agent environments:
- [DISCOVERY_AND_LOADING.md](DISCOVERY_AND_LOADING.md) — canonical discovery/loading contract;
- [ECOSYSTEM_GRAPH.json](ECOSYSTEM_GRAPH.json) — machine-readable capability and relationship map;
- [llms.txt](llms.txt) — absolute-link fallback for LLM/web environments;
- [AGENTS.md](AGENTS.md) — thin repository-instruction adapter for agent environments that support it.

Core distinction:

`DISCOVERABLE ≠ LOADED ≠ ACTIVE ≠ AUTHORIZED`

Relevance controls what should be loaded or activated now. It must not erase the rest of the ecosystem from discovery.

## New human user?

After the AI/agent discovery gate above, continue with **[FIRST_RUN.md](FIRST_RUN.md)**.

It is the practical adoption path for a human + AI pair, including:
- beginner and experienced-user entry paths;
- AI-as-teacher onboarding behavior;
- public/private separation;
- discovery and reuse of existing repositories;
- minimum private workspace bootstrap;
- a starter instruction for the user's AI;
- first Reality Check;
- first real project;
- when to add UnAiversed, rAIda, Watchdog or other machinery;
- continuity and graduation criteria.

The goal is not to copy the author's private ecosystem. The goal is to let each user build or reuse the smallest private environment their real work needs.

## Living governance

bAIble changes through evidence and experience:

`EXPERIENCE → CANDIDATE → GENERALIZE → VALIDATE → INTEGRATE`

Repeated failure is a signal to inspect the process, not a reason to endlessly patch the same incident or automatically create a new rule.

Reality outranks documentation.
