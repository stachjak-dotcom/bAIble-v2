# bAIble v0.1 — Foundation Bridge

This preserves the public conceptual foundation of bAIble v0.1 without pretending that the old repository is current v2.

## First principles
1. AI is a collaborator, not the final authority.
2. Desired outcome matters more than implementation.
3. Uncertainty is acceptable; silent guessing is not.
4. Meaningful mistakes can improve the system.

## Original discipline
Understand before implementing. Define the desired result. Make completion testable. Do not guess material rules. Respect scope. Record unrelated problems rather than silently expanding work. Reuse established patterns. Prefer small, verifiable changes. Separate implementation from verification. Preserve project memory. Distinguish experiment from production. Use explicit stop conditions.

## Original language
Explore → Propose → Prepare → Implement → Verify → Review.

## Original roles
Human / Product Owner, Architect, Developer, QA, Reviewer, Documentation Agent.

These remain explicit responsibilities in v2; newer coordination roles do not erase them.

## Historical boundary
v2 intentionally extends the foundation with stronger public/private separation, provenance, contextual relationships, coordination and continuity mechanisms. Those extensions are not original v0.1 material.
