# bAIble v2 — Source Coverage

This document records what source families were reviewed for the living v2 consolidation and how they are treated.

## Public bAIble foundation

Reviewed concepts from the original public bAIble include:
- core rules and first principles,
- original roles,
- Explore / Propose / Prepare / Implement / Verify / Review language,
- handoff discipline,
- agent evaluations,
- lessons learned.

Treatment: generalized and integrated into active v2 documents.

## bAIble pre-v2 laboratory

Reviewed active/lab material includes:
- onboarding and bootstrap variants,
- Reality Check and verification material,
- provenance, security and public/private guidance,
- Agent Roles / Agent Evals,
- WheeAIls and Wolf,
- workspace templates,
- experiments,
- origin/purpose and optional Song Two layer,
- migration/self-audit material.

Treatment: unique information extracted; redundant routes are not copied blindly.

## FederAItion

Reviewed generalized material includes:
- rAIda rules and runtime boundary,
- Watchdog continuity boundary,
- preflight / role / scope / authority discipline,
- evidence and verification state,
- durable decisions and lessons,
- orchestration research and context-management lessons,
- live runtime tests and workflow evidence.

Treatment: public contracts and lessons generalized. Private runtime details, identifiers and project-specific evidence remain private.

## UnAiversed

Reviewed material includes:
- Human Map / AI Map distinction,
- context relationships,
- observation → candidate → confirmed/rejected thinking,
- frequency-is-a-signal lesson,
- graph-record concept with first-class relation objects,
- stable addressable nodes,
- relation provenance/context/time/status,
- spatial rendering as optional presentation rather than source of truth,
- rAIda bridge direction,
- historical session maps used as evidence of context/meaning drift.

Treatment: generalized into ECOSYSTEM_MAP, RELATIONSHIP_MODEL, CONTEXT_ITEM, HUMAN_VIEW, AI_VIEW and FAILURE_MODES.

## What “everything” means here

The goal is **semantic coverage**, not a raw mirror.

We intentionally do not copy:
- private repository contents,
- private run IDs,
- credentials or access paths,
- project-specific implementation detail that is not reusable,
- duplicate documents whose unique content already has a canonical home.

A concept is considered integrated only when its meaning, responsibility, provenance and boundaries survive — not merely its filename.
